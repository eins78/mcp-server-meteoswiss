## What this delivers

Replaces GitHub Pages' broken branch-deploy (`source=main`, `path=/docs`) with a proper static
docs site (Astro + Starlight) built and published via GitHub Actions. The old setup only ever
served the repo-root `docs/` folder — `packages/meteoswiss-forecast-evals/docs/results/`, where
the actual promptfoo eval snapshot lives, was never reachable — and separately errored under
Jekyll despite a `.nojekyll` marker.

- **New package** `packages/meteoswiss-docs-site/` — standalone workspace (own
  `pnpm-workspace.yaml`, excluded from the root glob, same pattern as
  `meteoswiss-forecast-evals`). `scripts/sync-content.ts` assembles `src/content/docs/` from two
  source trees elsewhere in the monorepo: the repo-root `docs/` tree, and
  `packages/meteoswiss-forecast-evals/docs/results/` (markdown writeups synced into
  `forecast-evals/results/`, paired promptfoo static HTML snapshots copied byte-for-byte into
  `public/`, outside the content-collection pipeline). Each writeup gets an auto-injected link to
  its paired HTML snapshot when filenames pair by slug.
- Shared `site.config.mjs` (`SITE`/`BASE`) between `astro.config.mjs` and the sync script — Astro's
  `base` config does **not** auto-rewrite root-relative links already baked into markdown at build
  time (verified empirically: an unprefixed link survived a full build unchanged), so the prefix
  has to be injected by hand at sync time.
- Sidebar originally grouped by content type (Plans / Sessionlogs / Research / Test Reports /
  Forecast Evals — Results), autogenerated per directory — **superseded by the 2026-07-18
  re-scope below**, which cut this down to runs-only.
- **New workflow** `.github/workflows/pages.yml`: `withastro/action` builds, `actions/deploy-pages`
  publishes, both `push`-to-`main` and (build-only) `pull_request` triggered, scoped via `paths:`
  to docs-relevant changes.

## Bugs found and fixed during the build (not just Copilot findings)

- **Astro's `base` doesn't rewrite Starlight `hero.actions[].link` either** — clicking "Browse
  plans" on the local preview 404'd at `/plans/` instead of `/meteoswiss-llm-tools/plans/`.
  Verified against `Hero.astro`/`LinkButton.astro` source: the href is passed straight through, no
  base rewriting happens for that field (unlike sidebar autogenerate, which Starlight resolves
  from routing). First fix hardcoded the `BASE` prefix; a later Copilot round correctly flagged
  that as a drift risk against `site.config.mjs` — switched to a relative link (`plans/`, no
  leading slash) instead, which resolves correctly against the page's own base-prefixed URL
  without hardcoding anything.
- **That fix then exposed a deeper, pre-existing bug**: even with the link pointing at the right
  URL, `/plans/` and `/forecast-evals/results/` had no actual page there — Starlight's sidebar
  `autogenerate` doesn't synthesize a directory-index page. Fixed by adding two hand-authored
  landing pages (`src/content/docs/plans/index.mdx`,
  `src/content/docs/forecast-evals/results/index.mdx`) and generalizing the sync script's
  destructive clear step from whole-directory `rm` to file-level, walking and protecting a
  specific allowlist of hand-authored paths — the previous version could only protect a
  top-level `index.mdx`, not one nested inside an otherwise sync-managed directory.
- **Wide-table caveat flagged in the plan turned out to be a non-issue**: confirmed via
  `getComputedStyle` in a live preview that Starlight's own theme already sets
  `table { display: block; overflow-x: auto }` — no custom CSS needed.

## Copilot review loop

Six rounds of real findings, all fixed:

1. Two stale plan-doc cross-references (`sync-content.mjs` → `.ts`, "no automatic wiring for v1"
   claim overtaken by the auto-link feature) + the superseded options doc not marked as such.
2. README's workflow-path reference read as if `pages.yml` lived inside the package.
3. `titleFromContent()` fallback could leak directory separators into sidebar titles (fixed with
   `basename()`), and separately mangled H1 text by replacing `"` with `'` instead of properly
   YAML-escaping it in `ensureFrontmatter` (which already did this correctly one line down — the
   two were fighting each other).
4. Hero links hard-coded with `BASE` (see above) — switched to relative.
5. `tsconfig.json`'s `exclude` override dropped the implicit `node_modules` exclusion once any
   explicit `exclude` was set — added it back explicitly, matching `meteoswiss-mcp`'s convention.
6. `snapshotSlugs` was passed to *every* synced source, not just the forecast-evals-results one —
   coupled unrelated docs to the snapshot set; a future doc sharing a basename with a snapshot
   would've gotten an incorrect link. Added a `linkSnapshots` flag per `ContentSource`.
7. `pages.yml` had no `pull_request` trigger — a docs-site-breaking change could merge without any
   CI catching it, since this package sits outside `pr-ci.yml`'s workspace filter. Added one,
   scoped to the same `paths:` via a YAML anchor, with the `deploy` job gated to
   `github.event_name == 'push'` and its elevated `pages`/`id-token` permissions moved from
   workflow-level to job-level so a PR run never carries them.
8. Unused/buggy `start` script (`astro dev` without syncing content first) — removed; `dev`
   already covers the need. Stale symlink-skip comment citing a `docs/plans/delivered/` path that
   doesn't exist yet — generalized to point at the CLAUDE.md convention instead of a specific
   possibly-nonexistent example.
9. Workflow-level `concurrency: group: pages` meant unrelated PR builds would cancel each other
   (and get canceled by `main` pushes) — scoped to `pages-${{ github.ref }}` so `main` keeps
   "newer push wins" semantics while PR validation runs stay independent.
10. Two more stale-doc contradictions: the implementation plan's status line still said "awaiting
    Max's go-ahead" after the PR already implemented it; the superseded options doc's "Astro
    considered and set aside" reasoning (from the original raw-Astro-vs-Eleventy-vs-VitePress
    comparison) read as live guidance contradicting the supersession note — added a "Superseded by
    outcome" annotation explaining Starlight changes that calculus, kept the original reasoning
    for the historical record.

Adding the `pull_request` trigger (finding 7) paid off immediately: it fired for the first time on
the very push that introduced it, giving genuine pre-merge proof that `withastro/action`'s
`upload-pages-artifact` step succeeds (`github-pages.zip`, 1.49MB, artifact ID `8253185567`) —
something that's otherwise impossible to verify before merge, since GitHub's `workflow_dispatch`
refuses to target a workflow file that doesn't exist on the default branch yet, even with `--ref`
pointing at the PR branch.

Rounds 7 and 8 (re-requesting Copilot after the last real findings) both returned "reached their
quota limit" rather than completing a review — a genuine external constraint, not a code issue.
Did not keep retrying past the second failure.

## Favicon + Tailscale preview (2026-07-12)

Max wanted a live pre-merge preview and a favicon change (🌦️) before deciding whether to merge.

- Favicon: an SVG text-glyph favicon (`<text y=".9em" font-size="90">🌦️</text>`) at
  `public/favicon.svg`, wired explicitly via Starlight's `favicon: '/favicon.svg'` config option
  (matches the default it would've resolved anyway — set explicitly so it's documented, not an
  accident of file placement).
- Tailscale preview: `astro preview` backgrounded on `mac-zrh`, mapped tailnet-only via
  `tailscale serve`. Hit two real bugs along the way: (1) Vite's preview server 403s any request
  whose `Host` header isn't explicitly allowlisted (a DNS-rebinding protection) — fixed with
  `--allowed-hosts <tailnet-hostname>`; (2) a stale backgrounded process from earlier in the
  session was still holding the intended port, so Astro silently fell back to the next free one —
  killed the orphan, then just pointed `tailscale serve` at whatever port Astro actually bound
  rather than fighting it further. Verified reachability with `curl --resolve` (forces the
  correct IP while still doing a real TLS handshake against the actual cert and correct `Host`
  header — this sandboxed environment's shell has no MagicDNS resolution, so plain hostname
  curls/Playwright navigation fail with `ERR_NAME_NOT_RESOLVED` even though the route itself
  works; `--resolve` sidesteps that without weakening the check).

## Content re-scope to runs-only (2026-07-18)

Max reviewed the live preview and asked for a much narrower scope: "i dont want to serve plan,
logs, etc. just the promptfoo runs and some editorializing around it to explain them, and a
simple list on the index with teasers."

**Removed entirely** — repo-root `docs/` is no longer a sync source at all (previously synced
wholesale). Everything that lived there is now excluded from the public site:
- `docs/plans/**` (7 files: geocoding-fallback, nearest-station, ogd-integration, prod-promotion,
  chatgpt-fetch-compat, the two docs-site-generator planning docs)
- `docs/sessionlogs/**` (all session narrative logs, including this file)
- `docs/research/**` (RC test reports, UX reviews — internal QA dossiers)
- `docs/test-reports/**` (manual MCP tool test passes)

Nothing else needed excluding: `.delegate-status.md` isn't tracked in this repo/branch to begin
with (confirmed via `git ls-files`), and there's no `handoffs/` directory anywhere in the repo.
Was not unsure about any of the above — all four categories are unambiguously internal process
docs, not public editorial.

**What's published now**: only `packages/meteoswiss-forecast-evals/docs/results/*.md` (the
promptfoo run write-ups) and their paired `.html` snapshots — the same source that was already
scoped correctly, just no longer sharing the sync with the internal docs tree.

**New: required per-run editorial.** `editorial/<slug>.md` — one stub per run, a `teaser`
frontmatter field (used on the homepage list) plus a short "what this tests / how to read it"
paragraph, injected into the synced run page right after its frontmatter as an "## About this
run" section, ahead of the (more technical) original write-up. Wrote light stubs for both
existing runs, deliberately not trying to match Max's own editorial voice — flagged here as
something he'll likely want to refine himself. **A run without a paired editorial stub is now
skipped from publication entirely** (loud console warning, not a build failure) — enforces "every
run has editorial" as a publish gate rather than a suggestion, so a future dated run doesn't
silently ship without the explanatory framing.

**Homepage rewritten**: dropped the `template: splash` hero + 5-topic `CardGrid` (Plans /
Sessionlogs / Research / Test Reports / Forecast Evals) for a plain intro paragraph + a
`<LinkCard>` per run (title + teaser + link), generated from `src/data/runs.generated.json` — a
manifest `sync-content.ts` writes alongside the content sync. Removed the now-redundant
`forecast-evals/results/index.mdx` group-landing page (the homepage does that job now) and
`plans/index.mdx` (the whole section is gone). Sidebar collapsed from 5 groups to 1 ("Eval
Runs"). Hit one Starlight version gotcha: top-level `{ label, autogenerate }` was removed in
Starlight v0.39 — the error message named the fix (`{ label, items: [{ autogenerate }] }`)
directly, so no debugging needed.

`sync-content.ts` simplified substantially alongside this — the multi-source `ContentSource`
abstraction (built for 2 sources) is gone now that there's exactly 1; `clearSyncTargets` went
back to simple top-level-entry wiping (only `index.mdx` needs protecting now, no nested group
index pages). Also trimmed `.github/workflows/pages.yml`'s trigger `paths:` — `docs/**` no longer
affects this site's build, so it's no longer a trigger.

Verified via the same `curl --resolve` tailnet method as the favicon check: homepage shows only
the 2-run teaser list, `/plans/` and any sessionlog path now 404, both locally and over the real
tailnet route.
