# Unblock the 3.0.0 release: root-context Docker build + refreshed security pins

**Date:** 2026-07-24
**Source:** Claude Code (Opus 4.8, 1M context)
**Session:** Max asked to get `meteoswiss-mcp` v3.0.0 released and deployed after PR #117's merge-commit PR CI failed. PR: #138.

## Summary
PR #117 (the changesets release PR) merged to `main` and bumped `meteoswiss-mcp`→3.0.0 / `meteoswiss-skills`→1.1.0, but the merge-commit **PR CI failed** on two required checks, so nothing was ever released (npm still at 2.3.2, no `meteoswiss-mcp-v3.0.0` tag). This PR fixes both failing checks so the release can be cut and deployed.

## Root Cause
Two required checks failed on merge commit `f949292`:

1. **Docker Build Test** — The Dockerfile built from the *single package directory* (`context: packages/meteoswiss-mcp`) with `pnpm … --no-frozen-lockfile`, copying a **stale, unmaintained per-package `pnpm-lock.yaml`** (last synced 2026-03-29; still pinned `js-yaml@3.x/4.x` though `package.json` had moved to `^5.2.1`). `--no-frozen-lockfile` made the builder **re-resolve against the live registry**, which:
   - **dropped every root-level `pnpm.overrides` security pin** — the per-package `package.json` carries no `pnpm.overrides`, so a single-package resolution ships the image without `path-to-regexp@8.4.2`, `hono`, `undici`, `ws`, `form-data`, `ip-address`, etc. (a latent defect in *every* release image built this way); and
   - pulled the newest transitive versions (`js-yaml@5.2.2` pub 07-23, `undici-types@7.29.0` pub 07-24), which pnpm 10.34's built-in **`minimumReleaseAge`** (24h) then rejected: `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`. The *committed* versions (`js-yaml@5.2.1` 07-02, `undici-types@7.28.0` 06-15) all pass the gate.

   `release.yml`'s `publish-docker` builds the **same** Dockerfile, so this blocked the actual release, not just PR CI. (Supply-chain note: js-yaml genuinely shipped a 5.x line — `dist-tags latest=5.2.2`, lockfile integrity hashes match the real registry — so the blocked versions were legitimate, just too fresh. The policy was *not* weakened.)

2. **Security & Dependency Check** (required; `continue-on-error: true` spares the *run* but the check-run still reports `failure`) — `pnpm audit --audit-level moderate` newly failed on 4 HIGH + 1 MOD advisories: `fast-uri` (CVE-2026-16221), `brace-expansion` (CVE-2026-13149), `js-yaml`, and `@hono/node-server`. Notably `release.yml` runs **no** audit, so this gates only the fix-PR merge, not the publish.

## Fix
**Docker (Part A):** build from the **repository-root context** (`context: .` in both `pr-ci.yml` and `release.yml`) using the **frozen workspace lockfile** — which already pins the correct, age-compliant versions with all overrides applied and is validated by the passing "Lint, Build & Test" job. A `pnpm --filter meteoswiss-mcp deploy --prod --legacy` step produces a self-contained production tree (the package has no injected workspace deps, hence `--legacy`). Added a root `.dockerignore` (excludes `node_modules`, `dist`, and — critically — `.claude` worktrees, keeping the context small); deleted the stale per-package `pnpm-lock.yaml`. The runtime stage was also simplified to `CMD ["node", "dist/index.js"]`, dropping corepack/pnpm from the runtime image (removes a build-time network download from the release path).

**Security (Part B):** in the root `package.json` `pnpm` block:
- `fast-uri` override → **4.1.1** (the old `<3.1.2: 4.1.0` pin had gone stale *into* the new advisory's `>=4.0.0 <=4.1.0` range).
- `brace-expansion` overrides → **1.1.16** and **2.1.2**.
- `pnpm.auditConfig.ignoreGhsas` documents two advisories deliberately *not* force-fixed, each with rationale (flagged in the PR for Max's veto — the gate is not weakened):
  - `GHSA-pm4m-ph32-ghv5` **js-yaml** — dev-only, absent from the production image; 5.2.2 was age-blocked until ~22:55 UTC. **Fast-follow:** bump the devDep to `^5.2.2` once it clears the window.
  - `GHSA-frvp-7c67-39w9` **@hono/node-server** — a *Windows-only* path traversal; the deployment is Linux/Docker, and `≥2.0.5` is a breaking `1.x→2.x` bump on an MCP-SDK transitive dep.
